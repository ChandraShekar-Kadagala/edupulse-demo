Why this handbook exists

Almost every real website is two things: a way to collect information (forms) and a way to show information (tables). A hotel takes a booking through a form and lists bookings in a table. A university collects admissions through a form and publishes results in a table.

This guide teaches each element the way a senior developer would explain it at your desk: why it exists, how the browser treats it, when to reach for it, and the mistake everybody makes first.

  • University admission form — labels and validation attributes.
  • Student registration portal — inputs, name, id.
  • Feedback form — keyboard focus and tab order.
  • Academic results dashboard — tables, groups, colspan.

02 · HTML FORMS

The Complete Foundation

<form>actionmethodGETPOST
SOURCEThe form element creates an HTML form for user input. action is the URL where the form data is sent; method is the HTTP method used to send it — most commonly GET or POST.

What a form really is

A form is a container that collects values from controls and packages them for delivery. On its own it shows nothing; it gives every input, button and label inside it a shared purpose: “these values travel together to one address”.

Analogy · the hotel registration card

Paper card<form> — the container
Blank boxes<input> — where guests write
Printed captions<label> — “Full name”, “Email”
Reception deskaction — where the card goes
Postcard / envelopemethod — GET writes data on the outside (URL); POST puts it inside (request body)

Forms exist because HTTP needs structured data. Without a form you would have to build the request by hand; with one, the browser does the encoding, validation and sending for you.

Read it as: “When Book room is clicked, check that guest is filled, then POST guest=… to /book.” PRO NOTEOmit method and the browser uses GET; omit action and it submits to the current page URL.

Security: POST hides data from the URL but does not encrypt it. Only HTTPS encrypts. Never send passwords with GET.

Browser-side form handling (HTML does this)

Renders controls · lets users type and choose · checks required, min, maxlength, type · encodes name=value pairs · sends the HTTP request · displays the response page.

Server-side processing (needs Node, Java, PHP, Python…)

Receives the request at the action URL · re-validates every value · checks room availability · stores the booking in a database · returns a confirmation page or redirect.
MEMORY RULEaction = where, method = how. GET is a postcard, POST is an envelope.
EXAMPLEHotel search form → GET (shareable results URL). Booking form → POST.
COMMON MISTAKEBelieving the HTML form “saves” data. HTML only sends; a backend must receive and store.
INTERVIEW“Where does form data go with GET vs POST, and which should a login form use?”

04 · LABELS

Labels and Input Association

<label>foridimplicitexplicit
SOURCEThe label element creates a label for an input. The for attribute specifies which input the label is for. Implicit association wraps the input inside the label; explicit association uses for.

Why it exists. Text that merely sits near an input means nothing to the browser. A label creates a programmatic link: the browser, screen readers and voice-control software all know “this caption names that control”.

Analogy · name tags at an admission desk

Implicit = the student stands inside a booth with their name on it — no lookup needed. Explicit = a name tag reading “Seat 12” and a chair labelled id 12 — they can be far apart; the matching number connects them.
FIG 4 Label-to-input relationship: containment (top) vs for → id reference (bottom).

Accessibility gains

  • Screen readers announce “Email, edit text, required” instead of just “edit text”.
  • Larger click / tap area — vital for small checkboxes and on phones.
  • Voice control: users can say “click Email”.

Correct vs incorrect

WRONG<label for="Email"> + <input id="email"> — case mismatch, no link.
WRONG<label for="email"> + <input name="email"> — for matches id, never name.
WRONG<input placeholder="Email"> with no label — hint vanishes while typing.
RIGHTOne label per control; unique ids on the page; for copied exactly from the id.

Choose implicit when…

The label and control sit together: checkboxes, radios, “I agree” lines. Less markup, no ids to keep unique.

Choose explicit when…

Layout separates them (grid, table cell, two columns), or you need the id anyway for CSS/JS. Most production forms use explicit labels.

PRO NOTE Both at once

Nesting and for/id together is valid and extra-robust. A control may have several labels, but a label labels only one control.
MEMORY RULEfor points to id. Inside = implicit, pointing = explicit.
EXAMPLERegistration portal: <label for="roll"> + <input id="roll" name="roll">.
COMMON MISTAKEUsing placeholder as the only label, or duplicating an id so two labels fight.
INTERVIEW“Clicking my label does nothing. What three things do you check?”

Buttons, Fieldset and Legend

<button>submitresetbutton<fieldset><legend>
SOURCEThe button element creates a clickable button; its type (submit, reset, button) controls what happens when it is activated. fieldset groups related inputs; legend adds a caption describing that group.
FIG 5 Button behaviour comparison inside a form.
hotel/book

SOURCEFor <input type="button"> the value attribute is the button's text. <button> takes its text from its content instead.

Why you always write the type explicitly
A <button> with no type is a submit button. Put an “Add another guest” or “Show password” button inside a form without type="button" and every click submits the booking half-finished. Writing the type also tells the next developer your intent.
WRONG<button>Add guest</button> → submits
RIGHT<button type="button">Add guest</button>
FIG 6 Fieldset & legend grouping. A screen reader says “Room type, group — Deluxe, radio button, 2 of 3”.
hotel/book
Room type

Same name = one group (SOURCEonly one can be selected). Different values tell the server which one: room=deluxe. required on one radio makes the whole group required.

<button> vs <input type="button">

<button> can contain text, icons and markup; its text is its content. <input type="button" value="Help"> is a void element whose text comes only from value. Prefer <button>.

PRO NOTE fieldset superpowers

<fieldset disabled> disables every control inside it at once. <legend> must be the first child. Fieldsets can nest (e.g. “Guest 2” inside “Guests”).
WRONGReset placed next to submit — one slip wipes a long admission form.
WRONGA fieldset around a single field, or a legend outside the fieldset.

EXAMPLEFeedback form: “Rating” fieldset with 5 radios sharing name="rating".

Form Interaction and the Focused State

:focusTabShift+Taboutline:focus-visible
SOURCEThe focused state is the state of an input field when it is selected by the user.

In plain English: focus is “the control that will receive the next key you press”. Exactly one element on a page has focus at a time.

Analogy · the single microphone

On a panel only the person holding the microphone is heard. Pressing Tab passes the microphone to the next speaker; clicking someone hands it straight to them.
FIG 7 Unfocused vs focused input. The cyan ring is the focus indicator.

How a control receives focus

MouseClick the input itself
LabelClick its linked <label>
TabNext focusable element
Shift+TabPrevious element
TouchTap the field (keyboard opens)
ArrowsMove between radios in one group

PRO NOTEThe autofocus attribute and JavaScript el.focus() can also set focus. Leaving focus is called blur. Disabled controls can never be focused; readonly ones can.

Tab order follows source order

FIG 8 Focus currently on step 2. A radio group is one Tab stop.

Styling focus with CSS

WRONGinput:focus { outline: none; } with no replacement — keyboard users lose their place.

Why visible focus indicators matter

Keyboard-only users, people with motor impairments and screen-magnifier users navigate with Tab. Without a visible indicator they cannot tell which field they are typing into — like typing with your eyes closed. WCAG success criterion 2.4.7 Focus Visible requires a visible focus indicator for keyboard users.

PRO NOTE:focus-visible shows the ring for keyboard focus but usually hides it for mouse clicks; fieldset:focus-within can highlight a whole group while any child has focus.

Accessible interaction checklist

  • Every control reachable with Tab, in a logical order.
  • Focus ring clearly visible (contrast ≥ 3:1 with background).
  • Clicking a label focuses or toggles its control.
  • Never use colour alone to mark the focused or invalid field.
  • Test by unplugging the mouse: can you book a room?

07 · TABLES

HTML Table Fundamentals

<table><tr><th><td>
SOURCEThe table element creates an HTML table. tr creates a row, th creates a header cell and td creates a data cell.

What a table is: data that only makes sense when read across a row and down a column at the same time. “88” means nothing; “Asha Rao’s Maths mark is 88” needs both directions.

Analogy · the printed marksheet

Each student gets one line (row). Each subject gets one vertical slot (column). The bold top line names the columns (header cells). Every other box holds one value (data cells). HTML describes this sheet row by row, left to right.

PRO NOTEAdd scope="col" to column headers and scope="row" to row headers (e.g. a student's name) so assistive technology pairs every cell with the right header.
Use tables for tabular data only. Building page layout with tables makes screen readers announce “table, 3 columns” for a menu. Use CSS Grid/Flexbox for layout.
WRONGRows with different cell counts, or using <th> just to get bold text.

Where real projects use tables

EXAMPLEResults dashboard: one tr per student, one td per subject mark.
COMMON MISTAKEThinking in columns: HTML has no “column of cells” — you write rows.

Why group rows semantically?

  • Meaning: tools know which rows are headings, data and summary.
  • Styling hooks: thead th, tfoot td — no extra classes.
  • Printing: browsers can repeat thead/tfoot on every printed page of a long table.
  • Scripting: sort or filter only tbody rows; header and totals stay put.
Accessible header relationships. <caption> gives the table its accessible name (“Semester 3 Results, table”). <th scope="col"> lets a screen reader say “External, 70” as you move across a row.
Rules. caption must be the first child of table. Only one thead and one tfoot; tbody can repeat to split data into sections.
WRONGPutting totals in the last tbody row styled bold, or a colspan that makes row slot counts disagree.

Planning a colspan in three steps

3 · Removethat many − 1 cells from the row (2)

PRO NOTE Several tbody sections

One table, two logical blocks — each can be styled, sorted or collapsed separately.

MEMORY RULEHead, Body, Foot — like a letter: title on top (caption), greeting, content, signature.

10 · TOOLING

HTML Validator, DOM Inspector and DevTools

validatorDOMElementsConsoleNetwork
SOURCEAn HTML validator checks the syntax of HTML code to ensure it is valid. A DOM inspector lets you inspect and modify the HTML structure of a page. DevTools are web developer tools built into the browser that help you debug, profile and analyse pages.

Source HTML ≠ the DOM

Your source is the text file you wrote. The DOM (Document Object Model) is the live tree of objects the browser builds after parsing it — like a builder turning a blueprint into a building, fixing small blueprint errors on the way. DevTools shows the DOM, not your file.

The parser silently inserts <tbody> (and html/head/body if missing). That is why the Elements panel can show tags you never typed.

12 · INTERVIEW PREP

20 Technical Interview Questions

DEFDIFFPRACTICALDEBUGA11YSCENARIO
DEF1. What do the action and method attributes of a form do?action is the URL that receives the submitted data; method is the HTTP method (GET or POST) used to send it. Defaults: current URL and GET.
DIFF2. Explain GET vs POST with a real example.GET appends name=value pairs to the URL — ideal for a hotel search you can bookmark. POST sends them in the request body — right for creating a booking or logging in. Neither encrypts; HTTPS does.
DEBUG3. A field is filled in but the server never receives it. Why?Most likely the input has no name, or it is disabled, or it is an unchecked checkbox/radio, or it sits outside the <form>.
DIFF4. What is the difference between id and name?id must be unique and is used by labels, CSS and JavaScript; it is not submitted. name is the key in submitted data and may be shared, e.g. by a radio group.
DIFF5. placeholder vs value?A placeholder is a temporary hint that is never sent. A value is real data: it is displayed as content and submitted.
DIFF6. disabled vs readonly?Both block editing. Disabled controls cannot be focused and are not submitted; readonly controls can be focused and copied and are submitted — use readonly for a booking ID the server needs.
DEF7. Does size="4" limit input to four characters?No. size sets the visible width in characters. maxlength limits characters; min/max limit numeric values.
PRACTICAL8. How do you make three radio buttons mutually exclusive?Give them the same name (e.g. name="room") and different values. Wrap them in a fieldset with a legend.
DIFF9. Implicit vs explicit label association?Implicit nests the input inside <label>. Explicit uses <label for="x"> that matches id="x" on the input, so they can be separated in the markup.
DEBUG10. Find the bug: <label for="Email"> … <input id="email">for and id are case-sensitive: “Email” ≠ “email”, so the label is not linked. Make them identical and check the id is unique.
A11Y11. Why is a placeholder not a replacement for a label?It disappears as soon as the user types, often has low contrast, and is not reliably announced as the field's name. Labels stay visible and are always announced.
DEF12. What is a button's default type, and why specify it?submit. A “Show password” or “Add guest” button without type="button" would submit the form by accident.
PRACTICAL13. Does a reset button empty the form?Not necessarily — it restores each control to its initial HTML state. A field with value="1" goes back to 1.
A11Y14. Why use fieldset and legend for a radio group?The legend is announced as the group's name (“Room type, group”), giving context to short option labels like “Deluxe”. It also organises long forms visually.
A11Y15. A designer asks you to remove the blue focus ring. What do you do?Never remove it without a replacement: keyboard users would lose their place (WCAG 2.4.7). Restyle it with :focus/:focus-visible using a clear, high-contrast outline.
SCENARIO16. The form has required and maxlength. Is server validation still needed?Yes. Client-side rules can be bypassed by editing the DOM or sending a raw request. The server must re-validate, sanitise and authorise every value.
DIFF17. th vs td — and what does scope add?th is a header cell that describes data; td holds the data. scope="col"/"row" tells assistive technology which cells a header describes.
DEF18. Why use thead, tbody and tfoot?They give rows meaning (headings, data, summary), provide CSS/JS hooks, let headers and footers repeat on printed pages, and help assistive technology.
DEBUG19. A footer row with colspan="4" sticks out past a 4-column table. Why?The row has the spanned cell plus another cell = 5 slots. Make the counts match: colspan="3" + 1 cell = 4.
SCENARIO20. DevTools shows a <tbody> that isn't in your file. Explain.DevTools shows the DOM, not the source. The HTML parser inserts tbody automatically. The validator checks source syntax; the inspector shows what the browser built.
How to answer in an interview: definition in one sentence → a concrete example (hotel, university, results) → the trap or accessibility/security consequence. That three-step answer signals real-world experience.
